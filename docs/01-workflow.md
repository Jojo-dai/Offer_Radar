# 01 · 七步工作流详解

> 前 3 步一次性串行（确认后不再循环）；第 4-7 步每天循环。

```
 ┌──────────── 阶段一：建画像（一次性） ────────────┐
 ①简历上传 → ②画像分析 → ③多轮调整 → 【你点确认】
 └────────────────────────┬───────────────────────┘
                          ▼
 ┌──────────── 阶段二：日常循环（每天） ────────────┐
 ④采集入库(8:00/18:00/手动) → ⑤JEV打分
                          ▼
 ⑥投递清单确认【你授权→自己去投→回来标记】
                          ▼
 ⑦跟踪看板(9:30/19:30 同步反馈)
 └─────────────────────────────────────────────────┘
```

---

## 阶段一 · 建画像

### ① 简历上传与解析

**触发**：你在「① 简历画像」上传文件或粘贴文本

**输入格式**

| 格式 | 解析方式 | 说明 |
|---|---|---|
| `.docx` | mammoth | 保留段落结构 |
| `.pdf` | pdf.js | 逐页抽文本 |
| `.md` / `.txt` | 直读 | — |
| `.png` / `.jpg` | OCR | 截图简历也能用 |

**处理链**

```
文件 → 浏览器本地解析 → 纯文本 → 敏感信息脱敏 → 送入模型
                                    ├ 手机号 → [手机号]
                                    ├ 邮箱   → [邮箱]
                                    ├ 身份证 → [身份证]
                                    └ 详细住址 → [住址]
```

原始文件**不上传**，只有脱敏后的文本参与后续。

**输出**：一段纯文本简历内容（存在浏览器内存，随画像保存时一并写入 `profiles.resume_text`）

---

### ② 画像分析

**触发**：解析完成后自动进入，或你手动点「重新分析」

**模型调用**

```
system: 你是资深职业顾问，按 JEV 方法论从简历提取求职画像，只输出 JSON
user  : <脱敏后的简历文本> + <你的补充说明>
参数   : temperature 0.3 / response_format json_object / 120s 超时
```

**输出**（写入 `profiles`）

| 字段 | 含义 | 下游用途 |
|---|---|---|
| `target_profile.roles` | 目标岗位方向（2-3 个） | 打分时的职级/方向锚点 |
| `target_profile.level` | 目标职级 | 打分：职级维度 |
| `target_profile.industries` | 目标行业 | 打分：行业维度 |
| `target_profile.cities` | 目标城市（中文） | 展示与判断地点可行性 |
| `target_profile.cities_en` | 目标城市（英文，含 `, China`） | **领英搜索的 `location` 参数** |
| `keywords` | 中文关键词 3 个 | **猎聘搜索** |
| `keywords_en` | 英文关键词 3 个 | **领英搜索** |
| `competitiveness` | 竞争力证据（可核对的事实） | 打分时**唯一允许引用**的证据源 |
| `gaps` | 硬缺口 | 展示，不隐藏 |

> 关键词为什么固定 3 个：猎聘/领英各 3 个词是实测的平衡点——覆盖主要方向，又不至于让单轮采集过长而触发风控。

---

### ③ 多轮对话调整 → 确认画像

**能做**：改城市、加减关键词、调整目标职级、补充"我不考虑外包"这类约束

**机制**：每次对话都把「当前画像 + 你的新指示」重新喂给模型，产出新版本画像（旧版本 `is_active = false` 保留）

**关键节点**：点「确认画像」后 `confirmed = true`

- 只有 `confirmed = true` 的画像，采集任务才会执行
- 确认后 ①②③ 不再循环；想改随时重新走一次
- 应用里会显示「画像已确认 / 未确认」徽章

---

## 阶段二 · 日常循环

### ④ 岗位采集入库

**三种触发**

| 方式 | 时机 | 链路 |
|---|---|---|
| 定时 | 08:00 / 18:00 | 定时任务直接执行 |
| 手动 | 随时 | 应用写 `agent_tasks(collect_now, pending)` → 每小时检查点消费 |
| 补跑 | 机器休眠恢复后 | 有防重复守卫：先清 >2h 僵尸，再查 90 分钟内是否已有运行，有则静默退出 |

**猎聘采集**（无头浏览器）

```
3 个中文关键词 → https://www.liepin.com/zhaopin/?key=<kw>
  → 等 5s → 提取 a[data-nick=job-detail-job-info]
      title / link / salary / location / tags / company
  → 每词约 40 条 → 写 .workbuddy/tmp/liepin-<kw>.json
```

**领英采集**（你的真实 Edge）

```
前置门禁（见 docs/06-network.md）
3 个英文关键词 → /jobs/search/?keywords=<kw>&location=<cities_en[0]>
  → 截图 + 读可见 DOM → 每词最多 25 条
  → 卡片缺链接时用「岗位名 + 公司名」精确搜索补齐一次
  → 写 .workbuddy/tmp/linkedin-<kw>.json
```

**入库（全状态查重，本流程最容易做错的一步）**

```
取存量：SELECT ... FROM jobs WHERE owner_id=<uid> LIMIT 2000   ← 不加 status 过滤
  ├ 岗位键 = norm(公司) + '|' + norm(岗位)
  │    norm = 小写 → 删「招聘/诚聘/急招/热招/岗位/职位」→ 删空格与标点
  ├ 命中存量或命中本轮 → 跳过（M+1），即使链接/平台/薪资不同
  ├ 链接去 ?/# 后相同 → 跳过
  ├ 同岗位但库里缺链接/薪资/地点 → 只 UPDATE 补字段，不动 status
  └ 都不命中 → INSERT（上限 120 条/轮）
入库后自检：GROUP BY company, position HAVING count(*)>1 → 有则按保留规则清理
```

**为什么必须全状态查重**：如果只看「待确认」，那么你已经投递过的岗位、你已经明确不投的岗位，每天都会被重新采回来堆在清单里——这正是"重复严重、影响投递效率"的根源。

**运行记录**（`agent_tasks`）

| 状态 | 含义 | 应用里显示 |
|---|---|---|
| `processing` | 正在跑 | 🟡 进行中 |
| `done` | 正常收尾 | 🟢 已完成 + 统计摘要 |
| `failed` | 失败/超时 | 🔴 已失败 + `失败原因：…` |
| `merged` | 与进行中的一轮合并 | ⚪ 已合并 |

---

### ⑤ 自动打分

**时机**：随采集任务一起完成，不需要你操作

**输入**：`competitiveness` + `target_profile` + 本批岗位的 `position` / `jd_summary` / `salary` / `location`

**输出**：`jobs.match_score`（0-100）+ `jobs.match_reason`（≤30 字）

详见 [07-matching-jev.md](07-matching-jev.md)。

---

### ⑥ 投递清单确认（人机交界点）

```
最新岗位清单（待确认，按分数倒排）
   ├ 勾选 → 「✅ 批量授权选中岗位」 → 状态变 待投递，自动打开职位页
   └ 「✕ 不投了」 → 状态变 不合适，进「不投的岗位」页签

已确认投递（待投递）
   ├ 「🔗 去平台投递」→ 你在猎聘/领英亲手投递
   └ 回来点「📮 我已手动投递」→ 状态变 已投递，进入跟踪

不投的岗位（不合适）
   └ 「↩ 移回待确认」→ 回到最新清单（支持批量）
```

**系统在这里只做记录，不做投递。**

---

### ⑦ 投递跟踪

**反馈同步**（09:30 / 19:30）：读平台上的投递状态，写 `job_events`

| 事件类型 | 触发 |
|---|---|
| `授权投递` | 你点授权 |
| `已投递` | 你点「我已手动投递」 |
| `状态变化：待投递→已查看` | 平台显示 HR 已查看 |
| `状态变化：→面试中` | 收到面试邀请 |
| `放弃投递` | 你点「不投了」 |
| `恢复待确认` | 你从不投清单移回 |

**看板刷新**（08:40 / 10:00 / 18:40 / 20:00 + 切回本页立即同步）

> 为什么不用每 20 分钟轮询：数据每天只写 4 次（2 次采集 + 2 次反馈同步），盲轮询 90% 是空转。改成「跟数据写入事件对齐」后，你看到的永远是最新的，同时少 90% 的无谓请求。

**产出**：统计卡（投递/已查看/面试/拒绝/转化率）、投递漏斗、面试邀请列表、事件时间线。
