# 07 · JEV 五维匹配打分

## 方法论

JEV（Job-Experience-Value）结构化匹配：把「候选人画像」和「岗位要求」拆成 5 个可比维度，逐维度对照打分再加权，避免"整体感觉像"式的粗判。

| 维度 | 权重 | 看什么 | 打分依据从哪来 |
|---|---|---|---|
| 核心技能与岗位要求匹配 | **35%** | 岗位要求的硬技能 / 方法论 / 工具，候选人是否具备 | `competitiveness` + 简历原文 |
| 行业 / 业务领域 | 15% | 行业是否相关、业务模式是否熟悉 | `target_profile.industries` + `competitiveness` |
| 职级与经验年限 | 20% | 岗位职级 vs 候选人实际层级、带团队/独立贡献 | `target_profile.level` + 简历原文 |
| 薪资与地点可行性 | 15% | 薪资区间是否落在预期、城市是否可接受 | `target_profile.cities` + 岗位 `salary` / `location` |
| 与发展方向的契合 | 15% | 这个岗位是否推进目标方向，还是原地打转 | `target_profile.roles` + `gaps` |

```
score = round(0.35*技能 + 0.15*行业 + 0.20*职级经验 + 0.15*薪资地点 + 0.15*发展契合)
```

## 三条打分纪律

### 1. 只认真实证据

每个维度只能引用 `competitiveness`、`target_profile`、简历原文里**明确写着的事实**。

- ✅ "预算系统落地 30+ 客户" → 技能维度可以给高分
- ❌ "他应该懂大模型" → 不允许，简历里没有就不算

### 2. 证据不足按保守中间分

某维度信息缺失（例如岗位没写薪资），不给 0 也不给满分，取 50 上下。**宁可低估，不可高估** —— 虚高的分数会让你把时间浪费在不匹配的岗位上，这比漏掉一个机会更贵。

### 3. 硬冲突直接低分

以下任一情况，总分直接压到 50 以下，不允许其他维度拉回来：

| 硬冲突 | 例子 |
|---|---|
| 城市不可接受 | 目标上海，岗位在乌鲁木齐且要求坐班 |
| 职级跨度过大 | 目标总监，岗位是执行岗；或反过来要求 15 年经验 |
| 行业完全无关 | 目标企业服务，岗位是医药研发 |
| 明确排除项 | 画像里写了"不考虑外包"，岗位是外包驻场 |

## 输出格式

```json
{
  "results": [
    { "index": 1, "score": 88, "reason": "预算系统落地经验完全对口，缺口：无海外项目" },
    { "index": 2, "score": 45, "reason": "技能匹配但要求 15 年经验，职级冲突" }
  ]
}
```

- `index` 对应输入列表的序号（从 1 开始）
- `score` 0-100 整数
- `reason` **≤30 字**，格式固定为「得分主依据 + 最大缺口」

## 为什么要写 `match_reason`

只有分数没有理由，你无法判断是"系统误判"还是"确实不合适"，也无法反馈修正。一条 30 字的理由能让你在 3 秒内决定要不要看这个岗位。

反例（不允许）：`"匹配度较高"`、`"综合评估后给出该分数"` —— 没有信息量。

## 模型调用参数

```js
cloud.llm.chat.completions.create({
  model: <auto>,
  temperature: 0.3,                       // 打分要稳定，不要创造性
  response_format: { type: 'json_object' },
  messages: [
    { role: 'system', content: '你是岗位匹配评估器……严格只输出 JSON' },
    { role: 'user', content: '候选人画像：…\n\n岗位列表：\n1. 公司:…｜岗位:…｜薪资:…｜地点:…｜摘要:…' }
  ]
})
```

- **批量打分**：一次最多 20 个岗位，用编号列表减少 token 与调用次数
- **超时**：120 秒；失败重试 1 次
- **幂等**：只对新入库的 `待确认` 岗位打分；存量岗位不重复打分（除非用户手动点「按画像批量打分」）

## 已知局限

| 局限 | 说明 |
|---|---|
| 依赖 JD 摘要质量 | 摘要由采集环节生成，摘要粗糙 → 打分粗糙 |
| 薪资缺失影响 15% 权重 | 领英多数岗位不显示薪资，这部分按中间分处理 |
| 不做公司质量评估 | 不判断公司是否靠谱、是否有裁员风险 |
| 不做 HR 偏好推断 | 不推测"这个 JD 实际想要什么背景" |

这些局限是刻意的：越界推断会让分数看起来更"聪明"，也更不可解释。
