# 02 · 工作边界

> 这一节是产品的硬约束。二次开发、二次分发、用 AI 复刻，都请勿放宽。

## 一、不代投（最高优先级边界）

系统**没有任何自动投递能力**，也不应新增：

- ❌ 不点击「投递 / 立即申请 / Easy Apply」
- ❌ 不填写平台投递表单
- ❌ 不自动向 HR 发送打招呼消息
- ❌ 不批量海投

**「授权投递」的真实含义**

```
你点「✅ 授权投递」
  → 系统只做三件事：
     1) jobs.status 改为「待投递」
     2) 写一条 job_events（授权投递）
     3) 帮你打开职位详情页
  → 真正的投递动作 100% 由你在平台亲手完成
  → 你回来点「📮 我已手动投递」，系统才开始跟踪
```

**为什么坚持这条**：投递是不可逆的对外动作，涉及你的真实身份与职业声誉。让 Agent 代投，出错的代价由你承担，而它无法承担。这条边界不是技术限制，是产品伦理。

## 二、只读采集

采集环节只允许做两件事：**读页面、记结构化字段**。

| 允许 | 禁止 |
|---|---|
| 打开搜索结果页 | 点开职位详情页（多余请求 + 隐私暴露） |
| 读卡片上的公司/岗位/薪资/地点/链接 | 翻页、无限滚动加载 |
| 关键词之间 30-60s 随机间隔 | 高频连发、并发抓取 |
| 遇到风控立即停止 | 绕过验证码 / 人机验证 / 登录墙 |
| 失败写原因后跳过 | 无限重试（上限 2 次） |

**频率自我约束**：每轮 ≤ 3 关键词 × 1 页 × 25 条；每天 ≤ 2 次定时 + 少量手动。

## 三、不碰凭证

- ❌ 不索取、不存储、不使用任何第三方平台账号密码
- ❌ 不把登录态导出成 cookie 文件长期保存
- ✅ 领英采集复用**你自己浏览器里已有的登录态**（Edge 扩展通道），系统本身不登录
- ✅ 数据库只存岗位公开信息，不存 HR 姓名 / 电话 / 邮箱

## 四、数据隔离

- 4 张表全部开启 RLS，策略 `owner_id = auth.uid()`
- 用户之间互相不可见，没有跨用户的管理视图，没有"运营后台"
- **原始文件不上传**：docx / pdf / 图片都在浏览器本地解析，文件本身不经过任何服务器
- **落库的是脱敏文本**：解析后先做 PII 替换（手机号 / 邮箱 / 身份证 / 详细住址 → 占位符），再把脱敏结果的前 20000 字存入 `profiles.resume_text`。这行数据只有你本人能读（RLS 强制），但**它确实存在于云端数据库里**，不是"只在本地"
- 送给模型的是脱敏文本的前 8000 字
- 想让简历彻底不落库：可以用 [`09-portability-auth.md`](09-portability-auth.md) 第 7 节的视图方案限制 Agent 读取，或改为只存结构化画像、不存原文（代价是重跑流程要重传简历）

## 五、不做承诺

- 匹配度是**决策辅助**，不是录用概率，也不是"投了就有戏"
- 不生成虚构经历，不美化 `gaps`（缺口字段会如实保留并在画像里展示）
- 不承诺"投递量"，只承诺"把该看的信息整理好"

## 六、失败必须暴露

| 场景 | 要求 |
|---|---|
| 采集失败 | `status='failed'` + `note='失败原因：<≤40字>'` |
| 卡死超时 | 超过 2 小时仍 `processing`，由每小时看门狗切断并标注 |
| 请求重复 | 与进行中的一轮重合 → `merged`，不重复跑 |
| 领英不可达 | 跳过领英段，如实记录原因；猎聘与打分照常执行 |

**不允许**静默失败、不允许把失败写成"已完成 0 条"、不允许只写"出错了"这种无法定位的原因。

## 七、刷新与性能边界

- 不做盲轮询（曾经每 20 分钟跑一次，90% 空转）
- 刷新必须与数据写入事件对齐：采集完成、反馈同步完成、用户切回页面
- 单次列表读取上限：岗位 500 条、运行记录 20 条

## 八、可扩展的红线

如果要在本项目基础上加功能，以下改动属于**越界**：

1. 加自动投递 / 自动打招呼 → 越界
2. 把 RLS 关掉或放宽到跨用户可读 → 越界
3. 采集时把已有岗位重置为「待确认」→ 越界（会导致重复投递）
4. 领英重定向后改走直连继续抓 → 越界（拿到的是中国区内容，数据不可用）
5. 绕过验证码 / 用打码平台 → 越界
6. 让 Agent 代替你与 HR 谈判、回复消息 → 越界（对外沟通必须你本人）
